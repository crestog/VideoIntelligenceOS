How to run this

Twelve minutes of setup, then it runs unattended until you stop it. Everything it learns is pushed to Telegram as it goes, so nothing is lost when a session ends.

What this tab actually does

The capture tab put every reel into a Telegram channel. This tab reads them back out and watches each one with about thirty different systems — two speech models, two OCR engines, object and face detection, depth, scene cutting, colour and motion measurement, embeddings, and several vision-language models that describe what is happening and why it holds attention.

Everything each system says is written down as a claim: what was said, which pass said it, which model, which version of the settings, and which shot of the video it belongs to. Nothing overwrites anything. When two transcribers disagree about a word, the database has both, and the disagreement is a fact you can query.

Why it rotates. Two T4s hold about 28 GB of weights. Thirty passes do not fit at once, so they are grouped: load a group, run it over every video, drop it, load the next. A reel is downloaded and decoded once per group instead of once per pass — the difference between a week and an afternoon.

Before you start

1Get the Telegram credentials

The same four values the capture tab uses. If capture is already running, they are the same ones — this tab keeps its own copy because the two engines can run in different processes.

  1. Bot token — message @BotFather, /mytoken, pick your bot. It looks like 123456789:AA….
  2. Channel id — forward any message from the channel to @userinfobot, or open the channel on web.telegram.org and read the number from the URL. It starts with -100.
  3. API id and hash — sign in at my.telegram.org → API development tools. Any app name works. These are your account's, not the bot's.
If these ever leak, rotate them. A bot token is revoked with /revoke in BotFather; the API hash is regenerated at my.telegram.org. Nothing in this project writes either to disk.
2Get a Hugging Face token (optional)

Only diarize — the pass that works out how many people are speaking and when — needs one, because pyannote's weights are gated behind an accepted licence.

  1. Make an account at huggingface.co.
  2. Open pyannote/speaker-diarization-3.1 and pyannote/segmentation-3.0 and accept the terms on both.
  3. Settings → Access Tokens → New token, read access. Paste it into Setup.

Skip this and everything else still runs; the diarisation pass records itself as skipped, with the reason.

3Choose your passes

Open Passes. Every system is listed with what it costs and what it writes. Recommended is a good starting point — it leaves out only the heaviest deep-reading passes.

Two rules the engine enforces for you: a pass that needs another pass's output will not run without it, and a pass that cannot fit in your VRAM is dropped from the plan with the reason shown.

4Split the work across accounts

One Kaggle session gives 12 hours. Ten accounts give ten slices of the library running at once.

On each account, set workers in total to how many accounts you are using, and this one is number to a different value on each — 0, 1, 2 and so on. Videos are assigned by a hash of their key, so the slices never overlap and the accounts never need to talk to each other.

They merge automatically. Every account pushes its findings to the same channel as shards. Any session that ticks replay evidence shards on start pulls in everything every other account has published.
5Run the readiness check, then start

The check looks for ffmpeg, the Python packages each selected pass imports, free VRAM and disk, whether the bot can actually post to the channel, and whether there are any videos to process at all.

Amber lines are advisory — a missing OCR package costs you one pass out of thirty. Only the blocking ones stop the engine, and they are listed separately.

Then press Start. Watch the Run tab; leave the browser if you like, the engine does not need it.

Stopping and starting again

Stop whenever you want. The pass in flight finishes and is recorded, the last shard is published, and the engine goes idle. Start it again tomorrow, next week, or on a different account and it picks up exactly where it stopped — no reel is ever fetched twice and no pass is ever run twice on the same video.

If a Kaggle session is killed without warning, the leases held by that worker expire after forty minutes and the rows go back into the pool. You lose at most the passes that were mid-flight.

When something fails

  • A pass fails on every video — almost always a missing package. The Coverage tab groups failures by message; install what it names, then Requeue.
  • Out of VRAM — the engine drops every resident model and carries on. If it repeats, raise the extra VRAM headroom in Setup, which makes the cohorts smaller.
  • Everything skips with "artifact is missing" — ffmpeg is not on PATH. Nothing can be decoded without it.
  • "No API id" — the engine can only reach originals under 20 MB and cannot read capture records at all. Add the API id and hash.
